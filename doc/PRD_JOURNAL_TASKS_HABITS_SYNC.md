# PRD: Дневник × Задачи × Привычки — синхронизация, напоминания и дайджест

## 1. Контекст и проблема

- Пользователь ведёт дневник в чате с ассистентом, но действия из заметок не превращаются автоматически в задачи или привычки.
- Напоминаний по задачам и чек‑инам привычек не хватает; они разрознены и не связаны с календарём.
- Утренний дайджест не показывает ключевые дела и прогресс по привычкам.

Цель: связать дневник, задачи, привычки и систему напоминаний в единую потоковую логику на нашем стеке (Effect, Postgres/Drizzle, Redis queue, Telegram, Яндекс.Календарь).

## 2. Цели и нецели

### Цели
1. Предлагать создать задачи и привычки на основе новой записи в дневнике (вторым сообщением после подтверждения сохранения записи).
2. Поддержать естественные команды для задач/привычек: создание, листинг, завершение, логирование выполнения.
3. Реализовать напоминания: 
   - по времени — через события в Яндекс.Календаре (с VALARM);
   - без конкретного времени — Telegram‑напоминания (воркер очереди).
4. Показ в утреннем дайджесте: Top‑N задач на сегодня, «чеклист» привычек на сегодня, краткий статус.
5. Хранение в Postgres (Drizzle), сервисы на Effect, очередь в Redis, доставка в Telegram.

### Нецели (на этот этап)
- Полноценный менеджер проектов (проекты, зависимостей задач, оценки).
- Богатый UI вне Telegram/календаря.
- Сложные рекуррентные правила и автопланирование с ограничениями (v1 — простые паттерны).
- Каналы, кроме Telegram.

## 3. Метрики успеха

| Метрика | Цель |
| --- | --- |
| Доля записей, где показаны предложения действий | ≥ 60% новых записей |
| Конверсия предложений → созданные сущности | ≥ 35% |
| Доставка напоминаний в срок | ≥ 97% |
| Доля пользователей, использующих чек‑ины привычек | ≥ 40% в 30 дней |
| Ошибки воркеров/дублей | < 1% в день |

## 4. Персоны и пользовательские сценарии

### Персона: Занятый специалист
Хочет быстро фиксировать мысли, получать конкретные предложения «что сделать», видеть прогресс по привычкам и не забывать про важное.

### Сценарии
1. Как пользователь, я пишу заметку «Надо оформить визу и записаться в визовый центр на следующей неделе» и получаю вторым сообщением предложения: «создать задачу оформить визу (дедлайн пт)», «создать задачу записаться в визовый центр (событие в календаре?)».
2. Как пользователь, я пишу «Сегодня ходил в зал» — система предлагает отметить прогресс по привычке «Зал» или создать её (2 раза в неделю), если привычки нет.
3. Как пользователь, я говорю «Буду бегать 3 раза в неделю» — система создаёт привычку с нужной периодичностью и добавляет чек‑ины в вечерний опрос.
4. Как пользователь, я говорю «Завтра в 10 забрать посылку» — создаётся задача с дедлайном/временем и предлагается создать событие в календаре с напоминанием.
5. Как пользователь, я получаю утром дайджест: 3 главные задачи на сегодня, чеклист привычек на сегодня (с быстрыми кнопками), плюс статус по вчерашнему дневнику.

Acceptance (общий):
- После сохранения записи бот отправляет «предложения к действию» с инлайн‑кнопками «Создать», «Скрыть».
- Задачи и привычки можно создать напрямую командой/натуральной фразой.
- Задачи с временем — опция создать событие в календаре; без времени — Telegram‑напоминание.
- Лог привычек фиксируется по кнопке или из фразы в заметке («сегодня сделал X»).
- Дайджест показывает резюме: Top‑N задач, привычки сегодня, быстрые действия.

## 5. Функциональные требования

### 5.1 Извлечение действий из дневника
- Сервис `JournalActionExtractor` (Effect):
  - Вход: `entryId`, `userId`, сырой текст записи, AI‑метаданные (тон/теги).
  - Выход: массив предложений `Suggestion[]`, где элемент — `type: 'task'|'habit'`, `payload` (структурированные поля), confidence.
  - Триггер: после успешного `createJournalEntry` ставим джоб в Redis (idempotency по `(entryId)`).
- `SuggestionPresenter` отправляет второе сообщение с блоками:
  - Задачи: заголовок, дедлайн/время (если найдено); кнопки «Создать», «Изменить», «Отмена».
  - Привычки: имя, периодичность/цель в неделю; кнопки «Создать», «Изменить», «Отмена».
- При подтверждении вызываются соответствующие репозитории. Для трассировки сохраняется `source_entry_id` в созданной задаче/привычке/логе.

### 5.2 Задачи
- Поля: `title`, `description?`, `status (todo|done|cancelled)`, `due_at?`, `time_window?` (start/duration), `priority?`, `tags[]?`, `calendar_event_id?`, `source_entry_id?`.
- Действия:
  - Создать из фразы/инструмента.
  - Завершить/отменить.
  - Список: сегодня / неделя / просрочка.
  - Опционально спланировать слот и создать событие в календаре (Яндекс Календарь).
- Напоминания:
  - Если есть время/слот — создаём событие в календаре (VALARM ~10–15 мин до начала).
  - Если только дедлайн-дата — Telegram‑напоминание в заданное окно (например, 10:00 местного времени).

### 5.3 Привычки и логи
- Привычка: `title`, `weekdays (int[])` или `goal_per_week (int)`, `active`, `tags[]?`, `created_at`.
- Лог: `habit_id`, `date`, `value?`, `source_entry_id?`.
- Действия:
  - Создать привычку из фразы/инструмента.
  - Отметить выполнение сегодня (кнопка в дайджесте/вечернем пинге) или из текста записи («сегодня X»).
  - Отчёты: стрики, % выполнения за неделю.

### 5.4 Дайджест
- Новые модули: `tasks`, `habits`.
- `tasks`: Top‑3 задач на сегодня (+счётчик просрочек).
- `habits`: чеклист привычек на сегодня (кнопки «☑ Выполнено»).
- Настройки пользователя: включить/выключить блоки, лимиты N, часовые пояса.

### 5.5 Инструменты (AI Tools)
- `task_add(title, due?, time?, duration?, priority?, tags?)`
- `task_complete(id|titleLike)`
- `task_list(scope: today|overdue|week)`
- `task_schedule(taskId, start, duration)` → календарь
- `habit_add(title, days?|goalPerWeek?)`
- `habit_log(id|title, date?)`
- `habit_list()`
- `extract_actions(entryId)` — получить/повторно отправить предложения из записи

Все инструменты — Effect‑сервисы, регистрируются через `IntegrationRegistry`. Форматтеры готовят удобные Telegram‑сообщения с инлайн‑кнопками.

### 5.6 Хранилище (Postgres/Drizzle)
- Таблицы (миграции):
  - `tasks`: `id`, `user_id`, `title`, `description`, `status`, `due_at`, `start_at`, `duration_min`, `priority`, `tags[]`, `calendar_event_id`, `source_entry_id`, `created_at`, `updated_at`; индексы: `(user_id, status)`, `(user_id, due_at)`.
  - `task_reminders`: `id`, `task_id`, `remind_at`, `sent_at`; индекс `(remind_at)`.
  - `habits`: `id`, `user_id`, `title`, `weekdays int[]`, `goal_per_week int`, `active bool`, `tags[]`, `created_at`, `updated_at`.
  - `habit_logs`: `id`, `habit_id`, `date`, `value int`, `source_entry_id`, `created_at`; индекс `(habit_id, date)`.
  - (опционально позже) `journal_extraction_suggestions`: `id`, `entry_id`, `type`, `payload jsonb`, `status (pending|accepted|rejected)`, `created_at`, `resolved_at`.

### 5.7 Очереди и воркеры (Redis)
- `journal:extract_actions` — генерирует предложения для записи и отправляет сообщение пользователю.
- `reminders:dispatch` — каждые N минут: 
  - для задач без календаря и с наступающим `remind_at` → Telegram.
  - резервы/ретраи: до 3 раз, экспоненциальная пауза.
- `weekly:review` — сводка по привычкам/задачам в воскресенье.
- Idempotency: ключи по `(userId, entryId)` и `(taskId, remind_at)`.

### 5.8 Интеграция с Яндекс.Календарём
- Для задач со временем предлагаем создать событие; храним `calendar_event_id`.
- Используем существующую интеграцию и throttling. События с VALARM дают нативные пуш‑напоминания на устройства.

### 5.9 Безопасность и приватность
- Не включать чувствительные данные из заметок в напоминания; обрезать приватные фрагменты.
- Санитизация пользовательского ввода (теги, названия привычек, задач).
- Токены интеграций — только в зашифрованном виде.

## 6. Нефункциональные требования
- Надёжность: сбой одного модуля не ломает весь пайплайн; ретраи 3 раза.
- Масштабируемость: сервисы — чистые Effects; внешние вызовы параллелятся с контролем.
- Логи и метрики: трек событий «создано/отклонено предложение», «напоминание отправлено», латентности воркеров.
- Конфиг: переменные окружения для Redis URL, дефолтного часового пояса, окон напоминаний.

## 7. Архитектура (обзор)

```
Запись дневника → (Redis) journal:extract_actions → Предложения → Подтверждение
                                               ↘ (создать) → Tasks/Habits (DB) →↘
                                                                           Календарь (опц.)

reminders:dispatch → Telegram напоминания (если нет события)

Ежедневный дайджест → модули: tasks + habits → Telegram
```

Ключевые сервисы:
- `JournalActionExtractor`, `SuggestionPresenter`.
- `TaskRepository`, `HabitRepository` (+ `HabitLogRepository`).
- Воркеры: `reminders:dispatch`, `weekly:review`.
- Дайджест‑модули: `tasks`, `habits`.

## 8. UX и сообщения
- После `createJournalEntry`:
  - «📌 Нашёл 2 задачи и 1 привычку — создать?» → кнопки «Создать всё», «Показать по одной», «Отмена».
  - По одному: карточка с кнопками «Создать», «Изменить», «Пропустить».
- Привычки:
  - Вечером (20:00–21:00): «Как прошёл день? Отметить: Зал, Английский, Медитация».
- Дайджест:
  - «✅ Сегодня: 3 задачи · 1 просрочена · Привычки: 2 из 3». Кнопки: «Отметить», «Список».

## 9. План запуска (итерации)

### Фаза 1 — База (Self‑DB)
- Миграции: `tasks`, `habits`, `habit_logs`, `task_reminders`.
- Репозитории и инструменты: `task_add/complete/list`, `habit_add/log/list`.
- Дайджест: блоки `tasks` и `habits` (Top‑N, чеклист сегодня).
- Вечерний пинг дневника (без экстракции).

### Фаза 2 — Экстракция и напоминания
- `JournalActionExtractor` + сообщения‑предложения после записи.
- Воркеры напоминаний: Telegram для «без времени», календарь для «со временем».
- Быстрые кнопки в дайджесте/сообщениях (чек‑ин, «создать событие»).

### Фаза 3 — Улучшения и обзор
- Расширение парсинга естественных фраз («буду X N раз в неделю», «сегодня сделал X»).
- Недельный обзор прогресса (воскресенье) и мягкие рекомендации.
- Админ‑команды для отладки расписаний/джобов.

## 10. Риски и меры
| Риск | Митигирование |
| --- | --- |
| Ложные срабатывания экстракции | Показывать предпросмотр, требовать явного подтверждения |
| Недоступность Redis/календаря | Ретраи, деградация в Telegram‑напоминания, логирование |
| Таймзоны/переход на летнее время | Вычислять локально по TZ пользователя, хранить TZ в настройках |
| Перегрузка дайджеста | Лимитировать N, компактные форматы, настройки пользователя |
